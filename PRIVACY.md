# NanoChat Privacy Policy

_Last updated: 2026-05-21_

NanoChat is a Chrome extension that lets you chat with Chrome's built-in on-device AI model (Gemini Nano) and run summarize / translate / rewrite / proofread / language-detect actions on text and on the current page. Everything runs locally in your browser.

## TL;DR

- **No data leaves your device.** NanoChat makes zero network requests. The Manifest V3 content security policy declares `connect-src 'none'`, which blocks `fetch`, `XMLHttpRequest`, WebSocket, and similar APIs at the browser level.
- **No analytics, no telemetry, no accounts, no third-party services.**
- **Your chat history is stored locally and encrypted at rest.**
- **The developer (Quantable) cannot see, collect, or access anything you do in NanoChat.**

## What NanoChat stores, and where

All data is stored on your own device, inside your own Chrome profile. NanoChat never transmits any of it.

| Data | Where it lives | Why |
|---|---|---|
| Chat sessions (titles, message text) | `chrome.storage.local` (extension) or `localStorage` (single-file build), AES-GCM encrypted | So you can resume past conversations from the sidebar |
| Per-API options (temperature, top-K, system prompt, JSON schema, probe languages) | `chrome.storage.local`, AES-GCM encrypted | So your settings persist across sessions |
| Encryption key | `IndexedDB` (`nanochat-keys` database), as a non-extractable `CryptoKey` | Used to encrypt/decrypt the values above |
| Pending page-action context (temporary) | `chrome.storage.local`, AES-GCM encrypted | Hand-off between the right-click menu / popup and the chat tab; consumed and cleared on read |

**Image and audio inputs are deliberately not persisted.** They are passed to the local model in-memory and discarded.

**Encryption at rest** uses AES-GCM with a per-install key generated by `crypto.subtle.generateKey` and stored as a non-extractable `CryptoKey` in IndexedDB. This defeats casual disk inspection (e.g. grepping your Chrome profile directory). It does not — and cannot — defend against malware or another user with code-execution rights on your machine.

## What NanoChat sends over the network

Nothing.

NanoChat performs no network requests of any kind. The only "downloads" you may see in Chrome are Chrome itself fetching the Gemini Nano model component — that download is performed by Chrome, governed by [Google's Chrome privacy notice](https://www.google.com/chrome/privacy/), and is independent of this extension. You can watch its status at `chrome://on-device-internals`.

## Page actions (Summarize / Ask about this page)

When you click a page action — either from the right-click menu or from the toolbar popup — NanoChat reads content from the currently active tab so the on-device model can use it as context. Specifically:

- **Text**: the page's `document.body.innerText`, truncated to 30,000 characters.
- **Title and URL** of the tab.
- **Images (only with the *"(with images)"* variant)**: up to 10 of the largest already-rendered `<img>` elements on the page. Pixels are read from the existing painted image via `OffscreenCanvas` — no fresh network fetches are made. Cross-origin images without CORS headers taint the canvas and are silently skipped.

This content is written to `chrome.storage.local` (encrypted) and handed to the NanoChat tab, which feeds it to the local model. It is never transmitted off the device.

Page content is only captured when **you** click a page-action menu item or popup button — never in the background, never on page load, never on tabs you didn't act on.

## Permissions and why each is needed

The extension requests four permissions in [`manifest.json`](extension/manifest.json). Each is required for a specific user-facing feature.

- **`storage`** — Save chat sessions, per-API options, and the temporary page-context hand-off in `chrome.storage.local`. Without it, settings and chat history wouldn't survive a reload.
- **`contextMenus`** — Add the four "Summarize / Ask about this page" entries to Chrome's right-click menu. Used only to register and respond to those menu items.
- **`scripting`** — Inject a one-shot extraction function into the active tab when you trigger a page action, in order to read the page's text (and optionally pixels from rendered images). Used only on explicit user action.
- **`activeTab`** — Grant the extension temporary access to read the current tab's DOM at the moment you click a page action. Combined with `scripting`, this lets NanoChat work on any page you choose without requesting broad host permissions.

NanoChat intentionally does **not** request:

- Any `host_permissions` — no broad "read your data on all websites" prompt at install time.
- The `tabs` permission — page actions never enumerate other tabs' URLs or titles.
- `webRequest` / `webRequestBlocking` — no traffic inspection.
- `cookies`, `history`, `bookmarks`, `downloads`, `identity` — none of these are touched.

## What the developer can see

Nothing. There is no backend, no analytics endpoint, no error reporter, and no update channel beyond Chrome's normal extension auto-update mechanism (which delivers code, not data). The author of NanoChat receives zero data from your use of the extension.

## Children's privacy

NanoChat collects no data, from anyone, of any age.
