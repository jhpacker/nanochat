# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NanoChat is a zero-dependency private on-device AI chat app — positioned as a "nano version of ChatGPT" — built on Chrome's built-in `LanguageModel` API (Gemini Nano). It also surfaces the other Chrome built-in AI APIs as side tabs: `Summarizer`, `Translator`, `LanguageDetector`, `Writer`, `Rewriter`, `Proofreader`. All inference is local — no network calls, no server.

Requires Chrome 138+. Some APIs (Writer/Rewriter/Proofreader) are still origin-trial and may need flags at `chrome://flags`. Model status visible at `chrome://on-device-internals`.

## Build / test / run

No tests, no linter, no package.json. One build step:

```
node build.js
```

This inlines [extension/styles.css](extension/styles.css) and [extension/app.js](extension/app.js) into [extension/index.html](extension/index.html) and writes the result to the root [index.html](index.html). The build does **not** touch popup or background files — those are extension-only.

A tracked pre-commit hook at [.githooks/pre-commit](.githooks/pre-commit) rebuilds `index.html` and re-stages it whenever any of the three source files are staged, so manual `node build.js` runs aren't required. Enable it once per clone with `git config core.hooksPath .githooks`.

- **Single-file version:** open root [index.html](index.html) in Chrome (works from `file://`).
- **Extension version:** load [extension/](extension/) as unpacked via `chrome://extensions` → "Load unpacked". Clicking the toolbar icon opens a popup ([extension/popup.html](extension/popup.html), [extension/popup.js](extension/popup.js)) with quick actions; right-click on any page produces context-menu entries handled by [extension/background.js](extension/background.js).

## Single source of truth: `extension/`

The repo ships the app in two forms, but **`extension/` is the source of truth**:

1. **[extension/](extension/)** — the MV3 extension. The chat app itself is [extension/index.html](extension/index.html) + [extension/app.js](extension/app.js) + [extension/styles.css](extension/styles.css). Around it sits the extension shell: [extension/background.js](extension/background.js) (service worker — context menus, page extraction, tab handoff), [extension/popup.html](extension/popup.html) + [extension/popup.js](extension/popup.js) + [extension/popup.css](extension/popup.css) (toolbar popup), and [extension/manifest.json](extension/manifest.json). Persists chat state to `chrome.storage.local`. **Edit these files.**
2. **[index.html](index.html)** at the repo root — generated by [build.js](build.js) from the three core files (`index.html` + `app.js` + `styles.css`). Distributed via copy/paste, ZIP download, or `file://`. Has no popup or background — just the chat app. Persists chat state to `localStorage` via the runtime fallback in the storage layer ([extension/app.js:302](extension/app.js#L302)). **Don't edit by hand — it gets clobbered on the next build.**

MV3's default CSP forbids inline `<script>`, so the extension cannot consume the single-file form; the build only runs in the inlining direction. The same JS works in both contexts because the storage layer detects `chrome.storage` at runtime and falls back to `localStorage`.

## Architecture

**Tab + panel structure.** The chat-app UI is seven tabs, one per Chrome AI API. Each tab has an `id="panel-<name>"` section and a matching `data-tab="<name>"` button. Tab switching is handled by a single delegated listener near the top of `app.js`.

**Availability sweep.** On load, `sweepAvailability()` ([extension/app.js:47](extension/app.js#L47)) iterates `TAB_APIS` and calls `<Global>.availability(opts)` for each API. If the API global is missing or returns `"unavailable"`, the tab is greyed out and struck through via `disableTab()`. This is why tabs can appear disabled — it's intentional, not a bug.

**Per-API pattern.** Each panel follows the same shape: a "Check" button calls `<API>.availability()`, a "Run"/"Stream" button calls `<API>.create(opts)` then either awaits a result or consumes a `ReadableStream`. Streaming methods are `prompt()`/`promptStreaming()` for `LanguageModel` and analogous pairs for the others. Download progress is reported by attaching a `downloadprogress` listener inside the `monitor` option — see `makeMonitor()` ([extension/app.js:208](extension/app.js#L208)).

**Chat sessions (Prompt tab).** Sessions are stored as `nanochat_session_<id>` plus an index at `nanochat_sessions_index`. `saveCurrentSession`, `loadSession`, `deleteSession`, and `listSessions` (around [extension/app.js:697](extension/app.js#L697)) manage the sidebar. Titles are derived from the first user message via `deriveTitle()`. **Image and audio inputs are deliberately not persisted** — they would blow the `chrome.storage.local` quota fast (see comment at [extension/app.js:278](extension/app.js#L278)).

**Encrypted storage at rest.** All values written through the storage layer are AES-GCM ciphertext (`{ _enc: 1, iv, ct }` envelopes). The master key is a non-extractable `CryptoKey` generated on first use and kept in IndexedDB under `nanochat-keys`. This defeats casual disk inspection / grepping the Chrome profile dir; it does **not** defend against malware running as the user. See the storage layer starting at [extension/app.js:293](extension/app.js#L293).

**Page → chat handoff (extension only).** Right-click menu items and toolbar popup buttons both route through `performAction()` in [extension/background.js](extension/background.js). Four actions: summarize / ask, each in plain and "with images" variants. The flow:
1. Background extracts page text (+ optionally up to 10 large images, filtered by rendered area, via OffscreenCanvas re-encoding to WebP — cross-origin/tainted images are skipped, preserving the no-network promise).
2. Background writes a `nanochat_pending_context` object to `chrome.storage.local`, optionally tagged with `targetTabId` if a NanoChat tab is already open.
3. The chat app's storage listener picks it up, renders a context card above the input, prefills/auto-sends if requested. See `consumePendingContext()` in `app.js`.
4. When images are included, `captionPageImages()` opens a fresh multimodal `LanguageModel` session **per image** (avoids cross-image context bleed), asks for a 2–4 sentence description, and `buildContextPrefix()` folds the captions into the seeded context as text. This keeps the chat history text-only so regenerate/reload still has the image info, and avoids asking Gemini Nano to caption + summarize in one shot.

There is no selection-based action: the popup probed `window.getSelection()` and the context menu had an "Ask about selection" entry in earlier versions; both were removed in favor of "ask about this page (with images)".

**Markdown rendering.** Assistant messages are rendered with a tiny inlined `snarkdown` variant ([extension/app.js:88](extension/app.js#L88)) plus a custom `processTables()` preprocessor for GFM tables (snarkdown doesn't handle them), then passed through `sanitizeHTML()`. If you touch markdown, both the table preprocessor and the sanitizer need to stay aligned.

**Language probes.** `LanguageModel` and `Translator` advertise supported languages by probing `availability({ expectedInputs: [{ type: 'text', languages: [lang] }] })` for each candidate language. See the probe loops around [extension/app.js:1364](extension/app.js#L1364).

## Conventions worth knowing

- `chrome://` URLs cannot be navigated to from a web page. The "chrome://on-device-internals ⧉" button copies the URL to the clipboard instead.
- Options (temperature, topK, system prompt, JSON schema, probe languages) are auto-persisted with a debounce — see `scheduleSaveOptions()`.
- `setStatus(el, text, cls)` is the single source of truth for status pills; pass `'ok'`, `'error'`, or `'warn'` as the class.
- The MV3 manifest sets a tight CSP (`connect-src 'none'`, no inline script) to backstop the "no network" promise — don't relax it without thinking carefully about what you're allowing.
- `pickExistingNanoChat()` in [extension/background.js](extension/background.js) uses `chrome.runtime.getContexts()` rather than `chrome.tabs.query({ url })` — the latter silently returns `[]` without the `tabs` permission, which the extension intentionally doesn't request.
